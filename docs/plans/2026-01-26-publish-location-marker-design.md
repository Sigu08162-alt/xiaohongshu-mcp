# 发布图文扩展 location 与 marker_tags 设计

## 背景与目标
当前 `POST /publish` 仅支持标题、正文、图片、话题与定时发布，内部发布动作已支持地点与标记，但未对外暴露。目标是在不改变现有调用方行为的前提下，补充 `location` 与 `marker_tags` 两个字段，以满足发布时的地址标签与标记需求。

## 范围与非目标
- 范围：仅扩展图文发布接口 `POST /publish`。
- 非目标：不扩展视频发布、不新增其他高级字段（合集、群聊、可见范围等）。

## 设计概述
### API 字段
新增请求字段：
- `location`：地点名称（支持城市/商圈/POI）。
- `marker_tags`：标记列表，可为地点或用户昵称，系统智能匹配。

### 数据流
`PublishRequest` → `domainpublish.ImageContent` → `xiaohongshu.PublishImageContent` → 页面自动化设置地点/标记。

### 校验策略
- `location` 允许空字符串。
- `marker_tags` 允许空数组，建议过滤空白项并限制数量（上限 10），以降低 UI 选择失败风险。

### 失败策略
地点或标记设置失败时直接返回错误并中止发布，避免“已发布但地点未设置”的半成功状态。

## 工程原则评估
- KISS：只新增必要字段，不引入其他高级设置。
- YAGNI：当前明确需求仅为地点/标记，其他字段暂缓。
- SOLID：请求结构与领域模型保持职责清晰、接口隔离。
- DRY：字段映射集中在服务层，避免重复散落。

## 风险与缓解
- 风险：前端 UI 选择器变化导致地点/标记失败。
- 缓解：沿用现有选择器策略，必要时补充 Inspector 验证与日志。

## 测试建议
- 手工：在有登录 cookies 的环境发布一条图文，验证地点与标记是否生效。
- 回归：确认不传新字段时发布流程与旧版本一致。
