## Context
MCP 工具链当前存在分散的等待/轮询逻辑，部分使用硬编码时间或硬编码条件。需要统一为配置驱动，并在配置缺失时直接失败。

## Goals / Non-Goals
- Goals:
  - 所有 MCP 工具链轮询/等待逻辑可配置化
  - 启动时严格校验配置完整性
  - 按模块拆分配置，避免全局单一配置难以维护
- Non-Goals:
  - 非 MCP 工具链逻辑不在本次范围内
  - 不重构浏览器引擎或非等待相关逻辑

## Decisions
- 使用 `config.yaml` 作为统一配置入口，按模块拆分（如 `publish`, `draft`, `interaction`, `analytics`, `auth`）。
- 配置缺失即报错（不再默认兜底）。
- 轮询/等待配置包括：超时、轮询间隔、最大重试、状态选择器集合（如适用）。

## Risks / Trade-offs
- **BREAKING**：缺失配置将导致启动失败，需同步更新所有环境配置文件。
- 配置复杂度上升，需要更严格的校验与文档说明。

## Migration Plan
1. 定义模块化配置结构与必填字段。
2. 在代码层替换所有硬编码等待/轮询为配置读取。
3. 添加配置校验与清晰错误信息。
4. 更新示例配置与文档。
